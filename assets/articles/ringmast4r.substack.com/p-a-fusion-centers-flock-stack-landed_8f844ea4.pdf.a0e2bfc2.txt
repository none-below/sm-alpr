NCRIC is the Northern California Regional Intelligence Center. Fusion centers sit
above city PDs. They take tips, cases, and sensor feeds from many agencies and turn
them into regional intel. NCRIC is that shop for a large slice of Northern California.
The GitHub repo is not github.com/NCRIC/.... It is erhhung/ncric-alprs,
published from a personal account whose commits are signed
eyuan@maiveric.com. The description is blunt: ALPRS (AstroMetrics) Automated
AWS Infrastructure Deployment for NCRIC (GitHub, erhhung/ncric-alprs).

MaiVERIC / AstroMetrics is the contractor. OpenLattice-style ALPR plumbing is the
product. Flock Safety is a data source they wired in. The repo is Terraform, Auth0,
Rundeck, Postgres dumps, Postman environments, and a worker they nicknamed
Flapper: a CLI that pulls ALPR reads from Flock over REST.
Ottawa, Illinois published an intranet link to Flock’s hotlist. This repo publishes the
ingest pipeline and a database extract of the cameras that pipeline was pointed at.
flapper/README.md says Flapper runs on the Rundeck worker and retrieves ALPR
reads from Flock Safety via REST. docs/flock_api.md lists the calls:
POST /v1/auth/userpass
POST /v1/query
POST /v2/images
GET /v1/cameras
The config file flapper/config/flapper.yaml points a datalake named flock at
https://api.flocksafety.com/api, with username and password taken from
environment variables (FLOCK_USER, FLOCK_PASSWORD). The live secrets are not
sitting in that YAML as plaintext. The architecture is.
That is the vendor leak pattern: not “here is the production password in a screenshot,”
but “here is exactly which Flock API you hit, from which AWS account shape, on
behalf of which fusion center.”

A companion text dump, docs/flock-cameras.txt, is the same census as a table
of agency + camera name. docs/flock-agencies.txt rolls up counts. Examples
from the agency file: Atherton CA PD (50 cameras), Benicia (45), Fairfield (56), Ontario
CA PD (91), NCRIC’s own network (16), Kaiser Permanente Vallejo (13).
This is not a live CAD feed. It is a point-in-time extract of Flock camera inventory as
NCRIC’s integrator stored it: street-level names plus WGS84 coordinates. Plot the
inserts and you get a map of the Bay Area and Northern California Flock footprint this
system knew about.
We plotted 1,182 of them (one row was 0,0 and dropped) on a local HTML map built
from that SQL.
The repo is 500-plus files of real platform: EKS, GovCloud hints (us-gov-west-1,
alprsgov profile), Auth0 tenant maiveric.us.auth0.com, Postman prod and dev
environments for api.astrometrics.us, Java keystores, public TLS/IdP certs,
Rundeck job XML that talks to the same Postgres pattern.
Client IDs for Auth0 SPA/M2M/webhook apps appear in *.tfvars.example and
Postman JSON. Client secrets are empty or marked DO_NOT_STORE. SSH keys in the
examples are truncated. Flock passwords stay in ${} placeholders.
So: this is not a full credential dump. It is worse in a different way. It is a blueprint
plus a camera geofile for a fusion center’s Flock-fed ALPR warehouse.
We searched GitHub for a second copy of this pattern (api.flocksafety.com in
Terraform/YAML, Flapper, FLOCK_USER / FLOCK_PASSWORD). The NCRIC repo is the
only operational hit. API-catalog accounts republish docs. A dog-tracker app
mentions the hostname. A researcher repo (eric-muller/alpr) processes Flock

The NCRIC integrator published the agency footprint. Flock’s own infrastructure

Put this next to Ottawa PD.
Ottawa is the customer putting the officer portal on Pages. NCRIC/ALPRS is the
integrator putting the regional Flock ingest on GitHub. Flock does not have to “get
hacked” for the surrounding system to leak. The vendor itself published 806 paths into
its own operations. The agencies and vendors who bolt onto Flock publish enough to
reconstruct who is on the network and, in this case, where the cameras sit.
